# Feature Specification: Open-source macOS speech backend

**Feature ID**: `001-macos-backend`
**Created**: 2026-10-26
**Status**: Draft, ready for technical planning
**Input**: Re-create an improved, publishable backend from the recovered project,
without exposing secrets, with prerequisite checks and installation of missing software.

## Scope and decisions

This specification follows the stock specification template generated by
GitHub Spec Kit `1.2.4.dev0`. It defines product behavior and acceptance gates,
not an implemented installer or authorization to deploy.

Restore the native macOS speech service in a dedicated `backend` project.
Preserve German/English synthesis, MP3/WAV responses, and the frontend's
[existing API contract](../../frontend/README.md#preserved-interface-and-backend-contract).
Improve reproducibility, secret handling, installation safety, and diagnostics.

The live service and frontend container remain read-only. A future deployment
requires separate operator authorization. Writing this specification does not
authorize dependency installation, service registration, migration, or restarts.

Default decisions, chosen because interactive clarification was unavailable:

- Prerequisite inspection is check-only. Installation is a separate opt-in action.
- Authentication is enabled by default. Backend credentials never enter browser code.
- Installation targets a dedicated user-owned environment, not system Python.
- macOS 13 or newer on Apple Silicon or Intel is the initial support target.
  Both architectures must pass qualification before being advertised as supported.
- No Docker backend is promised: Linux containers do not supply macOS `say`.
- This delivery contains a specification and quality checklist only.

Out of scope: cloud speech providers, additional language catalogs, user accounts,
audio/text history, billing, public internet exposure, automatic remote deployment,
and changes to the running installation.

## User Scenarios & Testing

### User Story 1 - Diagnose a machine without changing it (Priority: P1)

An operator can determine whether a Mac is ready before installing anything.

**Why this priority**: Missing prerequisites must not result in partial deployment
or unsafe changes to an existing speech service.

**Independent Test**: Inspect prepared machines with missing, incompatible, and
working prerequisites, while recording filesystem, package, and service changes.

**Acceptance Scenarios**:

1. **Given** a supported Mac, **when** the operator runs the check-only command,
   **then** each prerequisite has a status, detected version, and safe remediation.
2. **Given** Windows, Linux, an unsupported macOS release, or an unqualified
   architecture, **when** checks run, **then** the report explains the unsupported
   synthesis runtime and installation is refused without changes.
3. **Given** absent Python, environment manager, ffmpeg, voices, credentials,
   a writable destination, or a free configured port, **when** checks run,
   **then** blockers are distinguished from optional capabilities and no install,
   download, key generation, application import, or speech synthesis occurs.

### User Story 2 - Install only missing prerequisites safely (Priority: P1)

An operator can explicitly prepare a user-owned backend installation and rerun
setup without replacing working software or interfering with another service.

**Why this priority**: A fresh checkout must be deployable without undocumented
packages or machine-specific launch scripts.

**Independent Test**: Run installation against isolated fresh and partially
prepared Macs, with network and permission failures injected.

**Acceptance Scenarios**:

1. **Given** explicit installation consent and an approved destination,
   **when** required tools are missing, **then** the installer presents the
   intended changes, installs the permitted prerequisites, and rechecks readiness.
2. **Given** a complete installation, **when** installation is repeated,
   **then** it makes no package, credential, configuration, or service changes.
3. **Given** a privileged change, unapproved package-manager bootstrap, missing
   macOS voice, or installer requiring a system UI, **when** unattended setup
   reaches that step, **then** it stops with instructions and a nonzero result
   rather than escalating or silently omitting the prerequisite.
4. **Given** an interrupted download or dependency failure, **when** installation
   exits, **then** existing working installations and the running service remain
   intact, and the report distinguishes completed work from pending work.

### User Story 3 - Generate speech through the existing frontend (Priority: P1)

A user can submit text through the frontend and receive playable, downloadable
audio without receiving the backend credential.

**Why this priority**: Backend restoration must preserve the working user journey.

**Independent Test**: Use browser-to-proxy-to-backend contract tests with fixture
audio, plus separately authorized native synthesis checks.

**Acceptance Scenarios**:

1. **Given** authenticated server-side integration, **when** MP3 or WAV is
   requested with an explicit supported locale and speed, **then** nonempty,
   correctly encoded audio is returned with the matching media type and filename.
2. **Given** auto-detection, **when** sufficiently long German or English text is
   submitted, **then** the corresponding voice is selected; short or ambiguous
   input follows the documented default, and unsupported detected languages fail clearly.
3. **Given** a missing optional UK voice, exhausted capacity, failed conversion,
   or elapsed deadline, **when** speech is requested, **then** the documented
   safe error is returned and a subsequent valid request can succeed.
4. **Given** an attacker-supplied Authorization header or malformed request,
   **when** the frontend proxy receives it, **then** it cannot select or reveal
   a backend credential, bypass validation, or proxy to an arbitrary upstream.

### User Story 4 - Operate and diagnose the service (Priority: P2)

An operator can distinguish a live process from a synthesis-ready service,
start it deliberately, and diagnose failures without exposing user text.

**Why this priority**: Correct installation alone does not establish readiness.

**Independent Test**: Vary executable, voice, permission, disk, and configuration
availability without restarting any existing production service.

**Acceptance Scenarios**:

1. **Given** missing synthesis prerequisites, **when** health/readiness endpoints
   are queried, **then** liveness can remain healthy while readiness reports 503.
2. **Given** explicit service-registration consent, **when** an operator installs
   a per-user service, **then** it uses configured paths and existing secrets
   without embedding credentials in service definitions or process arguments.
3. **Given** startup or synthesis failure, **when** diagnostics are collected,
   **then** request identifiers and safe categories are available, but text,
   credentials, raw subprocess output, and private machine paths are absent.

### User Story 5 - Publish and reproduce the project (Priority: P2)

A contributor can clone, test, and redistribute a project with documented
dependencies and no private deployment details.

**Why this priority**: Open-source readiness requires more than removing a token.

**Independent Test**: Inspect a clean release checkout and its reachable history,
then reproduce environment setup and mocked tests without private network access.

**Acceptance Scenarios**:

1. **Given** a clean checkout, **when** locked development dependencies are
   installed, **then** all mocked backend tests run without macOS voices,
   private services, production credentials, or undeclared dependencies.
2. **Given** a release candidate, **when** public-content and history checks run,
   **then** no secrets, private addresses, personal machine paths, runtime
   databases/logs, or recovery/checkpoint refs are included.

### Edge Cases

- Missing developer tools, stale package indexes, proxy/TLS failures, offline
  installation, insufficient disk space, read-only destinations, and paths with spaces.
- An existing incompatible interpreter or environment must not be overwritten.
- An occupied port must not lead to terminating the listener or picking another port silently.
- Concurrent installers must not corrupt the same destination or rotate its credential.
- Cancellation must not leave child synthesis processes or reusable credentials in output.
- Unicode text, JSON escape expansion, whitespace-only input, malformed JSON,
  non-finite speed, unknown fields, oversized/chunked request bodies, and shell metacharacters.
- Missing/revoked credentials and missing protected credential files fail closed.
- Abbreviations, decimal numbers, line breaks, and quoted sentence endings must
  not be mistaken for arbitrary subprocess commands or excessive sentence splits.
- Optional voice absence is not a blocker for default German/US-English readiness.
- Loss of temporary-directory access or disk space fails safely and cleans up owned files.

## Requirements

### Functional Requirements

#### Prerequisite inspection and installation

- **FR-001**: Provide separate check-only and explicit installation operations.
  Check-only MUST NOT install, download, create environments, modify configuration,
  register services, or synthesize audio. It may query versions, available voices,
  and port state using bounded read-only operations.
- **FR-002**: Check macOS version/architecture, `say`, supported Python, environment
  tooling, ffmpeg capabilities, required/optional voices, configuration validity,
  credential accessibility, destination access, available disk space, and port
  availability. Report dependency/version, pass/warn/fail, reason, and remediation.
- **FR-003**: Provide human-readable and machine-readable diagnostics with stable
  item identifiers. Exit `0` for ready, `1` for actionable blockers, and `2` for
  invalid invocation or an incomplete diagnostic operation. No raw secret values
  may appear in either format. Checks MUST have bounded timeouts and never hang
  on a permission prompt or interactive subprocess.
- **FR-004**: Installation MUST require explicit operator opt-in and present its
  planned changes before execution. Unattended mode requires explicit acceptance
  of that plan; it MUST refuse unapproved privileged actions rather than invoke
  `sudo`, weaken permissions, or bypass transport verification.
- **FR-005**: Install compatible Python and locked application dependencies into
  a dedicated user-owned location. Do not replace system Python, install global
  application packages, or upgrade unrelated working tools. Existing compatible
  dependencies are reused; incompatible managed environments require a deliberate
  replacement action rather than in-place destructive repair.
- **FR-006**: Obtain missing tools only through documented official distribution
  channels or an explicitly approved package manager. Do not execute remote
  shell text directly. Verify available publisher signatures/checksums and lockfile
  hashes; reject failed verification. Document downloads and licenses.
  If the chosen package manager itself is absent, stop with approved bootstrap
  instructions rather than silently installing it.
- **FR-007**: Provide a reproducible ffmpeg strategy with MP3 encoding and WAV
  support. Every Python package used to locate or supply ffmpeg MUST be declared
  and locked. The original deployment's undeclared ffmpeg-provider dependency
  MUST NOT be required accidentally. Check the actual executable and codecs.
- **FR-008**: Check required German and US-English voices and optional UK-English
  availability. If a required voice needs an OS-managed download without a
  supported unattended interface, provide exact user-facing setup instructions,
  report setup as incomplete, and recheck after the operator completes it.
- **FR-009**: Setup MUST be idempotent and serialize changes to one destination.
  Interrupted work must be reported accurately. Remove only newly created
  temporary artifacts; never remove existing installations, credentials, or
  services. Upgrades, credential rotation, service registration/start/restart,
  remote access, and uninstall are separate explicit operations.

#### Speech API and frontend compatibility

- **FR-010**: Preserve `POST /v1/audio/speech`, `GET /healthz`, and `GET /readyz`.
  The frontend continues to use its three existing `/api/` routes.
  Successful speech responses are binary audio, not JSON or persisted URLs.
- **FR-011**: Accept `input`, optional `model` fixed to `macos-say`, optional
  `language`, optional ignored compatibility `voice` of at most 128 characters,
  `response_format` (`mp3` default or `wav`), and finite numeric `speed`
  (0.5-2.0 inclusive, default 1). Reject unknown fields and whitespace-only input.
  Support locales `de-DE`, `en-US`, `en-GB` and aliases `de`, `en`.
- **FR-012**: Limit text to 5,000 UTF-16 code units to match the existing browser,
  reject unpaired surrogates, and enforce a 32 KiB encoded request-body limit
  while reading, including absent or misleading Content-Length. The proxy and
  backend MUST both enforce 32 KiB. This deliberately replaces the recovered
  proxy's 16 KiB limit so valid escaped Unicode requests are not inconsistently rejected.
- **FR-013**: Explicit supported locales bypass detection. Without a locale,
  fewer than 20 Unicode alphabetic characters use the configured default
  (`en-US` initially). Otherwise classify locally against the full language
  inventory, accepting only German/English and returning 422 for others.
- **FR-014**: Preserve paragraph/sentence-aware speech, the documented 0.4-second
  sentence and 1.2-second paragraph pauses, and a maximum of 100 speech segments.
  Test abbreviations and decimals. Map speed to a configurable base rate of
  180 words per minute by default. Produce MP3 at 128 kbps CBR or mono
  44.1 kHz, 16-bit PCM WAV, with `speech.mp3`/`speech.wav` disposition filenames.
- **FR-015**: Default to at most two concurrent synthesis operations with no
  unbounded queue, a shared 60-second operation deadline, and a 25 MiB audio
  response limit. Validate configuration ranges and enforce limits across all
  child operations. Exceeding capacity returns 503; timeout returns 504;
  oversized request/audio returns 413; invalid input/segment count returns 422;
  missing prerequisites return 503; unexpected synthesis failure returns 500.
- **FR-016**: Invoke executables without a shell and do not interpolate user
  text into commands. Keep text and intermediate audio in private per-request
  temporary storage only. Apply a finite temporary-disk budget, prevent
  concurrent filename collisions, clean up on all completion paths, and release
  permits and terminate owned subprocesses on timeout/cancellation.
  No process-wide or name-based process termination is permitted.
- **FR-017**: Report liveness separately from synthesis readiness. Readiness
  verifies credential/configuration availability, executables and required
  voices without generating speech. Health endpoints reveal no environment
  values, host paths, credentials, or full installed-software inventory.

#### Security, operations, and publication

- **FR-018**: Enable backend bearer authentication by default, require a nonempty
  credential, compare credentials safely, and fail closed on missing/invalid
  configuration. Authentication failures return 401 with a Bearer challenge
  before language detection or synthesis. Health checks remain credential-free
  and minimally informative. Do not silently inherit the deployed launcher's
  unauthenticated mode.
- **FR-019**: Support explicit environment or protected-file credential sources;
  refuse conflicting sources. Document credential provisioning and rotation.
  Any generated credential requires explicit setup consent, cryptographically
  secure generation, owner-only storage, and no overwriting on repeat installation.
  Never pass secrets in process arguments, URLs, generated examples, or logs.
- **FR-020**: Update frontend server-side integration to supply its configured
  backend credential without browser changes or browser-visible configuration.
  Docker supports a read-only secret file; local development supports protected
  file/environment configuration. The proxy overwrites client-provided upstream
  Authorization, allows only the existing endpoints, and fails clearly when
  required credentials are absent. Generated runtime files containing credentials
  must be private, excluded from images/source, and never logged.
- **FR-021**: Default both service exposure and development tooling to loopback.
  A shared backend credential protects the backend-to-proxy hop, not users of an
  exposed proxy. Non-loopback proxy/backend deployment therefore requires a
  separately documented access-control and TLS boundary. Trusted-network
  unauthenticated mode must be an explicit, warned opt-out; do not enable it
  automatically to make setup pass. Enable no wildcard browser CORS policy.
- **FR-022**: Log only safe operational metadata such as request ID, duration,
  status, selected locale, and format. Do not log text, auth headers, raw request
  bodies, query strings, raw subprocess output, or private machine paths.
  Error responses and support bundles use safe categories, not exception dumps.
  Diagnostics must redact secret-bearing configuration without printing it first.
- **FR-023**: Include a portable per-user macOS service example using
  operator-selected locations, a safe PATH, and protected credentials.
  Check prerequisites before explicit startup; fail rather than install software
  during normal application startup. Do not ship a real host address, username,
  absolute home directory, secret, or automatically registered service.
- **FR-024**: Provide public setup/operation documentation, safe example
  configuration, locked runtime/development dependencies, and repeatable mocked
  tests. Cover fresh setup, partial setup, check-only, rerun, failure recovery,
  authentication, frontend integration, voice installation, and explicit removal.
  Do not include raw recovery documentation or machine-specific service files.
- **FR-025**: Before publication, review all release files and reachable history
  for credentials, private infrastructure and personal-path exposure. Exclude
  environments, runtime data/audio/logs, secret files, caches, and checkpoint
  refs. Findings fail the release gate rather than being silently suppressed.
- **FR-026**: Include a maintainer-approved open-source license before release.
  Verify recovered-source ownership and compatibility of redistributed dependencies,
  language models, and ffmpeg components; retain required notices.
  Do not redistribute Apple's speech engine or installed voice assets.
- **FR-027**: Provide automated mocked API, installer, and frontend-integration
  tests independent of the production Mac. Native qualification uses isolated,
  authorized test machines and synthetic text only. Document tested OS/tool
  versions and architectures without implying unsupported compatibility.

### Key Entities

- **Speech request**: validated text, locale selection, format, speed, and optional
  compatibility fields; no permanent storage.
- **Synthesis result**: bounded audio bytes, media type, filename and request ID.
- **Runtime configuration**: validated host/port, voice choices, executable
  locations, limits and references to credentials, not embedded public secrets.
- **Prerequisite report**: item identifiers, detected versions, status, safe
  reasons and remediation; separate from minimally informative HTTP health.
- **Installation plan/result**: destination, proposed and approved changes,
  completed steps, pending manual steps, verification results, and safe failure
  categories. Does not itself grant permission to modify another machine.

## Success Criteria

### Measurable Outcomes

- **SC-001**: A successful check-only run produces zero intentional filesystem,
  package, credential, or service mutations and zero synthesis operations.
  OS-managed access/audit records are outside the tool's control.
- **SC-002**: Every required missing/incompatible prerequisite yields a named
  blocker, a nonzero exit, and actionable remediation. Readiness never reports
  success while a required dependency, codec, voice, or credential is absent.
- **SC-003**: On each qualified architecture, an authorized clean-machine setup
  reaches readiness using only documented steps; repeating setup produces zero
  changes. Manual voice installation remains an explicit incomplete state until verified.
- **SC-004**: All locale/alias, format, boundary-speed, auto-detection, size,
  authentication, capacity, timeout and cleanup acceptance tests pass.
  Native MP3/WAV samples decode correctly and match required encoding properties.
- **SC-005**: Requests at 5,000 UTF-16 units and 32 KiB encoded bytes are accepted
  when otherwise valid; one unit/byte above the respective limit is rejected.
  Tests include escaped Unicode, supplementary characters, lone surrogates,
  chunked input and false Content-Length.
- **SC-006**: Synthetic credential/text markers appear zero times in captured
  logs, error responses, diagnostic output, browser assets/network responses,
  image layers, and release artifacts, excluding the intended input field and
  authorized text request body. Public-history checks have no unresolved findings.
- **SC-007**: Failed/interrupted installation leaves the previous working service,
  credential, and environment unchanged; synthesis failure/cancellation leaves
  no owned running child process, leaked permit, or per-request temporary files.
- **SC-008**: Mocked backend and proxy-integration suites pass on non-macOS CI
  without real credentials, voices, synthesis, private network access, or access
  to the original installation.
- **SC-009**: A release contains a maintainer-approved license, required notices,
  supported-platform matrix, and complete declared dependency inventory; a
  contributor can reproduce setup from a clean checkout and the lockfile.

## Assumptions and release gates

- Recovery analysis established that application source and tests are intact.
  They are behavioral reference material, not permission to publish private
  runtime files or deployment-specific identifiers.
- Python 3.11 or newer is the starting compatibility baseline. Actual supported
  versions and installation artifacts must be qualified and pinned during planning.
- Downloading tools or voices requires internet access; normal synthesis and
  language detection do not. Offline setup reports missing prerequisites without
  attempting downloads. No offline bundle is required in the first release.
- The implementation plan must choose and verify one reproducible Python/tool
  bootstrap strategy, ffmpeg distribution, credential-file format, temporary-disk
  limit, and native qualification matrix against these requirements.
- A maintainer must approve the license and confirm ownership before public
  release. This is an explicit release gate, not an assumption of permission.
- No commit, push, installation, or deployment is part of this specification task.
